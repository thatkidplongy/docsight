# DocSight Conventions

Extends the baseline in `~/Develop/CLAUDE.md` (strict TS, no `any`, verb prefixed functions,
if guards, no nested ternaries in JSX, utils in `src/lib/utils/` with a colocated test each).
Rules here are project specific and take precedence.

## Providers

- All model access goes through the `Provider` interface in `src/lib/providers/provider.ts`.
  UI components, hooks and scripts never call `fetch` against a model API directly.
- New providers get their own file in `src/lib/providers/` and take configuration via their
  constructor, not via module level environment reads.

## Provenance

- A `Chunk` always carries `page` and `bbox`. Any transformation that drops provenance is a bug,
  even if the text survives.
- Span matching always compares `normalizeWhitespace()` output on both sides, never raw text.
- A `SpanCitation` may only render as a citation in the UI when `verified` is true. Unverified
  spans render as explicitly unsupported claims.

## Data and deployment

- The deployed site is static. It contains pre-computed demo answers and embedding files, and
  zero credentials. If a feature seems to need a server secret, redesign it (pre-compute or BYOK).
- `data/` artifacts are generated by scripts; never hand edit them. The gold set
  (`data/gold/`) is the exception: it is hand labelled and reviewed like code.

## UI states

- Every async view decomposes into named state components (`LoadingSkeleton`, `ErrorState`,
  `EmptyState`, content view). No inline conditional chains.

## Copy

- User facing copy avoids em dashes and hyphenated constructions; rewrite the sentence instead.
